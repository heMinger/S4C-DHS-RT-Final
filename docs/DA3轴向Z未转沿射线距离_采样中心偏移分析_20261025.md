# DA3 轴向 Z 未转「沿射线距离」导致采样中心偏移 — 代码级分析

> 整理日期：2026-10-25（修复方案于 2026-10-26 修正）
> 主仓库：`/home/lmh/s4c-DHS-RayTransformer`
> 结论性质：**已确认的语义不一致（bug）**，证据链已在代码中闭环。

## 1. 一句话结论

射线方向被归一化为单位向量后，采样参数 `z_samp` 的物理含义是**沿射线的欧氏距离**；而 DA3 输出的是**轴向 z 深度**（相机坐标系 z 分量，z-buffer 语义）。加载端只做了 `÷scale`，采样端直接把轴向 z 当作沿射线距离使用，导致采样中心实际定位在 `origin + z·unit_dir`，其轴向分量只有 `z·dir_z < z` —— **采样中心整体偏近，偏移量随像素偏离图像中心（θ 增大）单调增大，边缘最严重**。

正确关系应为：

```
d_ray = z / cos(θ)
```

其中 `cos(θ)` 是**相机坐标系**下射线方向与光轴的夹角余弦（即 `unproj_map` 归一化后的 z 分量），**不是** `rays[:,5]`（那是世界坐标 z 分量，见 §6 修正）。

## 2. 问题机制（数学）

- 归一化射线方向 `dir`（`‖dir‖ = 1`），3D 点 = `origin + z_samp · dir`，所以 `z_samp` 就是**沿射线欧氏距离** `d_ray`。
- 轴向 z 与沿射线距离的关系：`z = d_ray · cos(θ)`，其中 `cos(θ)` 是**相机坐标系**的方向余弦（相机朝向 +z，即 `unproj_map` 归一化 z 分量）。注意 `rays[:,5]` 是世界坐标 z 分量，不能直接当 cosθ（见 §6）。
- 代码把 DA3 的轴向 z 直接当 `d_ray` 用，等价于假设 `cos(θ)=1`（即所有像素都在光轴上）。
- 实际偏差：采样中心真实轴向分量 = `z · dir_z`，比真实表面近 `z · (1 - dir_z)`。

## 4. 结论与修复方向

证据链闭环：**渲染/采样用沿射线距离，DA3 用轴向 z，且二者在采样端未对齐**。

### 4.1 修复方向（2026-10-26 修正）

> ⚠️ 初版（2026-10-25）曾写成 `da3_depths / rays[:, 5]`，**这是错的**：`rays[:, 3:6]` 已由 `gen_rays()` 做 cam2world 旋转（`util.py`：`cam_raydir = R @ cam_unproj_map`），是**世界坐标系**单位方向；`rays[:,5]` 是世界 z 分量，**不是**相机坐标 cosθ。多视角/旋转相机下二者不等，直接除会引入新错误。

正确修复必须在**相机坐标系**计算 cosθ（DA3 轴向 z 是该相机光轴方向的 z-buffer 深度）：

1. 用每张图的内参 + 实际像素网格，在**该相机坐标系**计算 `cosθ = unproj_map[..., 2]`（归一化后 z 分量）。
2. 单独生成 `depth_distance = depth_z / cosθ`，仅供 DHS 采样使用。
3. 保留原始 z 深度供深度损失、评测使用，避免重复转换。
4. 验证图像中心/边缘及不同旋转相机的回投影关系后再开始训练对照。

```python
# 概念代码：cosθ 取自相机坐标 unproj_map（norm_dir=True）
cos_theta = cam_unproj_map[..., 2].clamp_min(eps)   # 相机坐标 dir_z == cosθ
depth_distance = da3_depths / cos_theta              # 仅 DHS 采样用
```

## 5. 影响面

- 影响所有走 `sample_adaptive`（DA3 引导自适应采样）的模型：**基线（原始设计 S4C+DHS+RT）、E1（DHS+RT 图像特征）**。
- 不影响 `sample_coarse`（均匀分层采样）、也不影响 E0（无 DHS，`adaptive_sampling=false`）。
- 偏移量与像素视场角相关：图像中心（θ≈0）几乎无影响，边缘像素（大 θ）采样中心明显偏近。

## 6. 修正记录与后续实验顺序（2026-10-26）

### 6.1 关键修正：rays[:,5] 是世界坐标分量，不是相机 cosθ

`gen_rays()`（`util.py:244-270`）：

```python
cam_raydir = torch.matmul(
    poses[:, None, None, :3, :3], cam_unproj_map.unsqueeze(-1)
)[:, :, :, :, 0]
```

`cam_unproj_map` 是相机坐标单位方向（`unproj_map(norm_dir=True)`），左乘 `poses[:,:3,:3]`（cam2world 旋转）后 `cam_raydir` 变为**世界坐标**单位方向。故 `rays[:,5]`（dz）是世界 z 分量，仅在相机无旋转（相机 z 轴与世界 z 轴对齐）时才等于相机 cosθ。DA3 的轴向 z 是**该相机光轴**方向深度，转换必须用相机坐标 cosθ。

### 6.2 修正优先级

单位问题优先于"窗口是否太窄"实验——先修正单位，否则扩大窗口可能只是在补偿错误采样中心（真实表面 Z=20m、夹角45°时，正确沿射线距离 28.28m；直接用 20m 采样，中心实际轴向深度仅 14.14m）。修正不需要新增 3D 监督，只需已有先验 + 相机几何。

### 6.3 修正后的实验顺序

| 顺序 | 对照 | 要回答的问题 |
|---|---|---|
| 第一组 | 原实现 vs 只修正 Z→距离 | 单位错误造成多少损失？ |
| 第二组 | 修正后原窗口 vs 修正后 1.5×窗口 | 单位正确后窗口是否仍不足？ |
| 第三组 | 修正后 RT39 vs RT103 | E1 图像输入是否进一步有效？ |

各组成对保持初始化、训练步数、损失、采样点数一致；论文 Ours 仍为历史基准。正在进行的 E1 28500 评估可继续完成（修正前的重要记录），但仅改评测无法消除已进入权重的训练偏差。

### 7.2 修复注入点选择（为何在 sampler 而非 loader/renderer）

`PatchRaySampler`（训练，`trainer.py:70`）与 `ImageRaySampler`（验证，`trainer.py:81`）是唯一能把 `da3_depths` 从 `(n,v,1,h,w)` 展平为**逐射线、与射线一一对应**的位置，且此处持有每视图 `focals`/`centers`（来自 `projs`），可直接在相机坐标系算 cosθ。`sample_adaptive`（`nerf.py`）只拿到展平后的逐射线深度，已丢失像素/视图对应关系，无法正确转换；loader 端转换则会污染原有深度损失与评测（那些确实用 z 深度）。故选择在 sampler 注入。

### 7.4 修正后的数据流（仅 DHS 采样）

```
da3_depths (n,v,1,h,w, 轴向 z-buffer)
   │  sampler.sample（Patch/Image）
   │  cosθ = cos_theta_map(w,h,focals,centers)   # 相机坐标 dir_z
   │  depth_distance = da3_depths / cosθ.clamp_min(1e-6)
   ▼
sample_adaptive(z_samp = depth_distance)   # 沿射线欧氏距离，语义对齐
   │
   ▼
points = origin + z_samp · unit_dir        # nerf.py:334
```

原始轴向 z 深度仍原样供深度损失与评测使用（未改动 `load_depth`/`distance_to_z`）。
