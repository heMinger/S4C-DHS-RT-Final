## 二、正确性与严谨性审查

### 2.1 需修正或澄清的点

#### （1）基线 absrel_prior 与配置不一致

- **文档声称**：当前基线 `absrel_prior=0.35`
- **实际配置**：`exp_kitti_360.yaml` 中为 `absrel_prior: 0.10`
- **建议**：确认“latest run”实际使用的配置；若基线确为 0.10，则 Exp A/B 的对比基准需统一，避免与真实实验不符。

#### （2）v3 absrel 数值略偏乐观

- **文档**：v3 多视图 absrel ~0.08–0.10
- **既有评估**（test_metric_vs_nested / test_fisheye_da3_depth）：
  - 透视 ALIGNED abs_rel：**0.105**
  - 鱼眼 ALIGNED abs_rel：**0.139**
- **建议**：表述改为“v3 透视 absrel ~0.10–0.12，鱼眼 ~0.14”，更符合实测，且对 absrel_prior=0.12 的选用更自洽。

#### （3）Exp A 的“无代码改动”不够准确

- **文档**：Phase 1 写“无代码改动，纯配置切换”
- **实际情况**：`kitti_360_dataset.py` 中鱼眼深度仍为 `np.zeros`，未从 v3 读取 image_02/03
- **影响**：Exp A 若仅改 `depth_da3_path`，鱼眼视图仍为全零深度 → 只有透视使用 v3，并非完整 offline v3
- **建议**：在 Phase 1 中明确：若要做**完整** v3 验证，需在 dataset 中增加鱼眼深度加载；若仅验证透视，可保留“无代码改动”，但需说明“仅透视使用 v3”

#### （4）Exp A 使用 absrel_prior=0.35 的合理性

- **文档**：Exp A 保持 absrel_prior=0.35，“与当前基线一致”
- **问题**：v3 透视 abs_rel ~0.10–0.12，median_ratio ~0.92；0.35 对应的是 OLD/单图（abs_rel~0.37）的窗口宽度
- **后果**：v3 深度更准，却用 0.35 的宽窗口 → 32 个点散布过宽，表面附近密度不足，可能弱于“适度收紧”的设置
- **建议**：Exp A 可考虑改为 absrel_prior=0.15（略大于 0.12，留余量），以更好体现 v3 的精度优势；若坚持 0.35，应在文档中说明这是“保守对照”而非最优

#### （5）5.3.5 数值示例中的 norm_conf

- **文档**：conf=6.0 时 norm_conf=1.0
- **按公式**：`norm_conf = clamp((6.0 - 1.0) / 5.5535, 0.1, 1.0) = 0.90`
- **建议**：将“高置信 6.0”改为 conf=6.55，或注明 conf=6.0 时 norm_conf≈0.9，σ≈0.12/0.9×d≈0.133×d，避免读者按表误解

## 三、Exp B 合理性分析（重点）

### 3.1 设计逻辑 ✓

- **问题定义准确**：全局常数 σ 无法利用 conf，二值 fallback 存在硬边界
- **解决方案合理**：用 conf 连续调制 σ，高 conf → 窄窗，低 conf → 宽窗
- **与 v3 数据匹配**：透视 conf 多集中在高端（clip ~30%），鱼眼分散，自然形成不同采样策略

### 3.2 公式正确性 ✓

```
σ(d, c) = max(min_thickness, absrel_prior / norm_conf × d)
norm_conf = clamp((conf - 1.0) / 5.5535, 0.1, 1.0)
```

- conf=6.55 → norm_conf=1 → σ=0.12×d
- conf=1.0 → norm_conf=0.1 → σ=1.2×d（近全范围探索）
- 数学关系正确，无除零风险

### 3.3 参数设置合理性

| 参数 | 文档建议 | 审阅结论 |
|------|----------|----------|
| **absrel_prior** | 0.12 | ✓ 合理。v3 透视 abs_rel ~0.10–0.12，取 0.12 与误差尺度一致，高 conf 时 2σ/d≈0.24 |
| **conf_epsilon** | 0.1 | ✓ 合理。避免 norm_conf→0 导致 σ 无穷大；0.1 对应 σ_max=1.2×d |
| **min_thickness** | 0.5 | ✓ 与现有一致，防止近距 σ 过小 |
| **CONF_MIN/MAX** | 1.0 / 6.5535 | ✓ 与 v3 实际范围一致，固定边界避免 batch 间不一致 |

### 3.4 边界情况 ✓

- conf 缺失 → 填 1.0 → norm_conf=0.1 → 最大 σ，保守合理
- batch 内全 6.55 → norm_conf=1 → 无除零
- depth≤0 → 仍走 invalid_depth fallback，逻辑正确

### 3.5 与当前实现的对比 ✓

- 当前 σ=0.35×d（或 0.10×d，取决于实际配置）：窗口约 0.7×d 或 0.2×d
- Exp B 高 conf：σ=0.12×d，窗口 0.24×d
- “采样密度约 3 倍”的表述在 absrel 从 0.35→0.12 时成立；若基线为 0.10，则提升约为 0.12/0.10=1.2 倍，文档可补充说明与基线 absrel 的对应关系

### 3.6 简化 fallback 的合理性 ✓

- 去掉二值 low_conf_mask，仅保留 invalid_depth
- 低 conf 通过大 σ 实现“宽窗探索”，等效于 softer fallback
- 连续过渡，无硬边界，设计合理

## 四、预期效果评估

### 4.1 Exp B 预期（文档：a1_lidar +0.01–0.03，IoU +0.5–1）

- **判断**：**偏乐观但可接受**
- **理由**：conf σ 调制主要是采样精细化，不改变 loss 形式。高 conf 区域采样更集中，有助于表面重建，但收益受限于：
  - 高 conf 像素比例（~30% 透视，鱼眼更低）
  - NeRF 对采样密度的敏感度
  - 其他瓶颈（如几何先验、场景覆盖）
- **建议**：预期可表述为“a1_lidar 有望提升 0.005–0.03，IoU 提升 0–1.5 点”，并注明“若提升不明显，需排查 conf 加载与调制是否生效”

### 4.2 Exp A 预期（文档：a1≥0.84，接近或略优于 online）

- **判断**：**合理**
- v3 多视图深度优于 online 单图 → 透视采样质量提高，有望略优于 online
- 鱼眼若仍为零深度，则与 online 行为一致；若加载 v3 鱼眼深度，则有望进一步优于 online

### 4.3 Exp C 预期（文档：a1 ~0.88–0.90，IoU ~62–65）

- **判断**：**偏乐观**
- 深度监督是结构性改动，潜力大于 Exp B，但具体幅度依赖：
  - lambda 调优
  - DA3 深度与 LiDAR 的对齐程度（v3 median_ratio ~0.92，仍有 ~8% 尺度偏差）
  - 深度 loss 与 RGB loss 的平衡
- **建议**：表述为“a1 有望达 0.86–0.90，IoU 有望达 61–65”，并强调需对 lambda 做调优
