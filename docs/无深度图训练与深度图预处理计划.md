# 无深度图训练与深度图预处理计划

> 在 s4c-adaptive-sampling1 中：不提供深度时如何有效训练；如何利用深度图预处理流程。

---

## 一、当前逻辑回顾

- **有深度时**：`data["depths"]` 非空 → trainer 得到 `da3_depths` → 设置 `adaptive_config` → 渲染器走 `sample_adaptive()`（DA3 引导的表面+全局采样）。
- **无深度时**：`data["depths"]` 为空或未提供 → `da3_depths=None` → `adaptive_config=None` → 渲染器走 `sample_coarse()`，即**全局逆深度分层采样**（与原始 S4C 一致）。
- 因此**无深度训练在行为上就等于 S4C**：所有射线均用 `sample_coarse()`，在逆深度（disparity）空间线性划分 64 点 + 分层抖动（`lindisp=True`），无自适应、无鱼眼退化。若不需要 DA3 先验，该模式即可稳定训练；瓶颈在于当前代码默认“总是加载深度”（trainer 写死 `return_depth=True`），需显式支持“不加载深度”的配置。

---

## 二、在没有生成深度图的状态下如何训练才有效

### 2.1 行为目标

- 训练阶段**不加载任何深度**（不读 DA3 PNG、不跑在线深度），`data["depths"]` 为空。
- 渲染器自动使用 `sample_coarse()`，所有视图（含鱼眼）均为**全局逆深度分层采样**（64 点，disparity 空间线性+抖动，与 S4C 一致），无鱼眼退化问题。
- 评估阶段若需 LiDAR 指标，可保留 `return_lidar_depth=True`（仅评估用，不参与采样）。

### 2.2 需要做的改动

| 步骤 | 位置 | 内容 |
|------|------|------|
| 1 | 配置 | 在 `configs/data/kitti_360.yaml` 或实验配置中增加开关，例如 `use_depth_for_training: false`（或复用 `adaptive_sampling: false` 表示“本实验不用深度”）。 |
| 2 | 数据 | 当 `use_depth_for_training=false` 时，构造的 Dataset 不加载深度：在 `datasets/data_util.py` 中根据该开关传 `return_depth=False`（仅 train；val/vis 可按需仍为 True 以便评估/可视化）。 |
| 3 | Trainer | 在 `models/bts/trainer.py` 的 `get_dataflow()` 中，**不要**对 train_dataset 写死 `return_depth = True`，改为根据配置设置，例如：`train_dataset.return_depth = config.get("use_depth_for_training", True)`。 |
| 4 | 可选 | 若希望“无深度”与“关闭自适应”语义一致，可让 `model_conf.adaptive_sampling` 与 `use_depth_for_training` 联动：无深度时自动不建 `adaptive_config`（当前已是：无 `da3_depths` 就不建，无需改）。 |

这样即可在**没有生成任何深度图**的前提下，用均匀采样完成整轮训练，且行为与原始 S4C 一致，对收敛更稳。

### 2.3 训练命令与配置示例

- 无深度训练：`use_depth_for_training: false`，且不设 `depth_da3_path` 或不在该路径下放文件。
- 有深度训练：`use_depth_for_training: true`，并配合下文“深度图预处理”使用离线或在线深度。

## 三、如何利用深度图预处理过程

深度图可以从“离线预生成”或“在线生成”两条路接入；推荐以**离线预处理为主**，在线仅作补充或调试。

### 3.1 方案对比

| 方案 | 深度从哪来 | 何时生成 | 优点 | 缺点 |
|------|------------|----------|------|------|
| **A. 离线 DA3（当前主流）** | 预生成的 PNG，`depth_da3_path` | 训练前脚本批量跑 DA3 | 训练时零深度开销、可复现、可版本管理 | 需先跑一遍预处理；鱼眼目前填零，需在渲染侧做无效深度回退（P1） |
| **B. 在线 Dataset（DA2）** | Dataset `__getitem__` 里调用 Depth Anything V2 | 每个 batch 加载时按张推理 | 不依赖预生成目录、可换模型 | 训练慢、DataLoader 易成瓶颈；当前需在 data_util 传 `online_depth_generation=True` |
| **C. 在线 Trainer（DA3）** | Trainer 前向前对整批图像跑 DA3 | 每个 step 前对当前 batch 的图跑 DA3 | 与当前设计一致、batch 级 GPU 推理 | 需在 model_conf 中设 `online_depth_generation: true` 并保证 DA3 可用；每 step 增加耗时 |
| **D. 独立预处理脚本** | 脚本写出的 PNG，与 A 相同读取方式 | 训练前一次性跑完 | 同 A；且可统一 DA3/DA2、分辨率、目录结构 | 需维护脚本与目录约定 |

### 3.2 推荐：以“离线预处理 + 训练时只读”为主

1. **预处理阶段（训练前执行一次）**
   - 使用**独立脚本**（见下节）对 KITTI-360 训练/验证集图像跑深度模型（DA3 或 DA2），写入统一目录，例如 `data_2d_depth_da3/{seq}/image_00|01/data_rect/{id:010d}.png`，格式与现有 `load_depth` 约定一致（如 uint16，scale=256）。
   - 鱼眼（image_02/03）可选：若不生成则保持“不写文件或写零”，训练时在渲染器对无效深度回退均匀采样（P1）。

2. **训练阶段**
   - 配置：`return_depth: true`，`depth_source: "da3"`，`depth_da3_path: "<预处理输出目录>"`。
   - `data_util.py` 已传 `depth_source`、`depth_da3_path`、`depth_da3_scale`，Dataset 的 `load_depth()` 会从该目录读取；无需再改数据接口。
   - 在渲染器中实现 P1：对“深度无效”（如 ≤ near 或全零）的射线使用 `sample_coarse()`，其余使用 `sample_adaptive()`。

3. **可选：在线 DA3 作为补充**
   - 在 `model_conf` 中增加 `online_depth_generation: true`，并在 trainer 中保留现有“有 depths 用 data，否则用在线 DA3”的分支，用于未预处理到的数据或调试；正常训练仍以离线为主。

## 四、实施计划（分阶段）

### 阶段 1：无深度图也能稳定训练（最小改动）

- **目标**：不依赖任何深度图，训练使用均匀采样，与原始 S4C 一致。
- **步骤**  
  1. 在 `configs/data/kitti_360.yaml`（或 exp 配置）中增加 `use_depth_for_training: false`。  
  2. `datasets/data_util.py`：构造 KITTI_360 时，若存在 `use_depth_for_training` 且为 false，则传 `return_depth=False` 给 train Dataset（test/vis 可单独配置）。  
  3. `models/bts/trainer.py`：`get_dataflow()` 中，train 的 `return_depth` 改为从配置读取，例如 `config.get("use_depth_for_training", True)`，不再写死 True。  
- **验证**：`use_depth_for_training: false` 下启动训练，确认 `data["depths"]` 为空、渲染器走 `sample_coarse()`，且无报错。

### 阶段 2：深度图预处理流水线

- **目标**：训练前生成并落盘深度图，训练时只读。
- **步骤**  
  1. **预处理脚本**：新增脚本（如 `scripts/preprocess_depth_kitti360.py`）  
     - 读 KITTI_360 的 split（如 `train_files.txt` / `val_files.txt`），遍历 (seq, cam, img_id)；  
     - 仅对透视相机（image_00, image_01）调用 DA3（或 DA2）推理，保存到 `depth_da3_path` 下与 `load_depth()` 一致的路径与格式；  
     - 支持多进程/多 GPU 与断点续跑（已存在的 PNG 可跳过）。  
  2. **配置约定**：在 `configs/data/kitti_360.yaml` 中注释说明 `depth_da3_path` 须指向该脚本输出目录；保持 `depth_source: "da3"`、`depth_da3_scale: 256.0`。  
  3. **训练**：`use_depth_for_training: true`，`depth_da3_path` 指向预处理输出；训练时不再运行深度网络，仅 Dataset 读 PNG。

### 阶段 3：鱼眼与无效深度回退（P1）

- **目标**：有深度图时，避免鱼眼（或其它无效深度）拖累收敛。
- **步骤**  
  1. 在 `NeRFRenderer.sample_adaptive()` 中，对每条射线判断深度是否有效（例如 `da3_depths <= near + eps` 或全零视为无效）。  
  2. 对无效射线调用 `sample_coarse(rays_subset)`，将得到的 64 点写回总采样矩阵中对应位置；其余射线仍用当前 `sample_adaptive()` 逻辑。  
  3. `sample_coarse()` 在本项目中 `lindisp=True`，即**逆深度（disparity）空间**线性分层采样，与 S4C 的 coarse 一致，不是深度空间均匀。  
  4. 可选：在 Dataset 中鱼眼仍返回零深度，或预处理脚本不写鱼眼，渲染器统一按“无效深度”回退到该全局逆深度采样。

### 阶段 4（可选）：在线深度与配置贯通

- **目标**：需要时可用在线 DA3/DA2，且配置一致。
- **步骤**  
  1. `datasets/data_util.py`：从 config 读取 `depth_mode`（或 `use_online_depth`），若为 online 则传 `online_depth_generation=True` 给 Kitti360Dataset；若使用 DA2，Dataset 已有 `_generate_depth_online`，只需保证 `depth_source` 与 `load_depth` 分支一致。  
  2. Trainer：若希望在线 DA3，在 `model_conf` 中设 `online_depth_generation: true`，并保证 trainer 内在线 DA3 分支被触发（当前因 model_conf 未传该字段而未启用）。  
  3. 文档中说明：推荐生产训练用“预处理 + 离线”；在线仅用于补数或调试。

---

## 五、小结表

| 场景 | 配置要点 | 渲染器行为 | 建议 |
|------|----------|------------|------|
| **无深度图** | `use_depth_for_training: false`，不提供/不读深度 | 全部 `sample_coarse()`，全局逆深度分层 64 点（= S4C） | 阶段 1 实现后即可稳定训练 |
| **有深度图（离线）** | `use_depth_for_training: true`，`depth_da3_path` 指向预处理输出，`depth_source: da3` | 有效深度用 `sample_adaptive()`，无效/鱼眼回退 `sample_coarse()`（全局逆深度） | 阶段 2 + 阶段 3 |
| **有深度图（在线）** | Dataset 或 Trainer 的 online 开关打开，并传入相应 config | 同上有/无深度分支 | 阶段 4 可选 |

按上述计划，**在没有生成深度图时**通过关闭 `use_depth_for_training` 即可有效训练；**要利用深度图时**以离线预处理为主、在线为辅，并在渲染侧对无效深度做回退，即可兼顾效果与稳定性。
