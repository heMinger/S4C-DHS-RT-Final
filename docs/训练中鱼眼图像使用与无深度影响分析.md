# 训练中鱼眼图像使用与无深度影响分析

> 基于 KITTI-360 数据流与 kitti360-mono 帧分配、PatchRaySampler、DA3 自适应采样的完整追踪。

---

## 一、数据加载阶段

每个训练样本加载 **8 个视图**，顺序如下：

| 索引 | 来源 | 类型 |
|------|------|------|
| 0 | image_00, frame_0 | 透视左（关键帧） |
| 1 | image_00, frame_1 | 透视左 |
| 2 | image_01, frame_0 | 透视右 |
| 3 | image_01, frame_1 | 透视右 |
| 4 | image_02, frame_0 | **鱼眼左** |
| 5 | image_02, frame_1 | **鱼眼左** |
| 6 | image_03, frame_0 | **鱼眼右** |
| 7 | image_03, frame_1 | **鱼眼右** |

鱼眼原图通过 `FisheyeToPinholeSampler.resample()` **重采样为针孔模型**（用透视内参 K 做重投影），输出 192×640 的“虚拟针孔”图像。之后代码统一用透视内参 `K_fisheye = K_perspective` 对待鱼眼视图，几何上按普通针孔相机处理。

**深度**：透视视图从 DA3 离线 PNG 加载；鱼眼视图在 `kitti_360_dataset.py` 中硬编码为**全零**：

```python
depths_f_left = [np.zeros((1, *fisheye_size), dtype=np.float32) for _ in img_ids_fish]
depths_f_right = [np.zeros((1, *fisheye_size), dtype=np.float32) for _ in img_ids_fish]
```

---

## 二、帧分配阶段（kitti360-mono）

v=8 视图被随机分为 **4 个 loss 视图 + 4 个 render 视图**：按 4 个相机各取 1 帧做 loss、1 帧做 render。

- **鱼眼视图（索引 4–7）会进入 `ids_loss` 和 `ids_render`**，与透视视图地位相同。
- 每个 step 通常有约 **2 个鱼眼视图做 loss、2 个鱼眼视图做 render**。

---

## 三、射线采样阶段（有射线采样吗？——有）

`PatchRaySampler` 对 `ids_loss` 中所有视图做射线采样：

```python
patch_coords_v = torch.randint(0, v, (self._patch_count, ))  # v = len(ids_loss) = 4
```

64 个 patch 在 4 个 loss 视图（含鱼眼）中**均匀随机**分配，平均每个 loss 视图约 16 个 patch = 1024 条射线。

**结论：鱼眼视图与透视视图一样参与射线采样。**

---

## 四、鱼眼视图在 NeRF 渲染中的两个角色

| 角色 | 说明 |
|------|------|
| **作为 loss 视图** | 从鱼眼采样的射线做体渲染得到 RGB/分割预测，与该鱼眼图像 GT 比较算 loss。 |
| **作为 render 视图** | 在 `ids_render` 中时，用于 `sample_colors()`：3D 点投影到鱼眼视图 `grid_sample` 取颜色。该路径**不依赖 DA3 深度**，只依赖投影，因此不受“无深度”影响。 |

---

## 五、无深度在自适应采样中的具体影响

鱼眼深度全零进入 `NeRFRenderer.sample_adaptive()` 后：

- `da3_depths = 0` → `clamp(min=z_near=3)` → 有效深度 d = 3
- σ = max(0.5, 0.10×3) = 0.5
- Surface 采样范围 = [d−2σ, d+2σ] = [2, 4] → clamp 到 [3, 4] m

因此 **32 个 surface 点全部挤在 [3, 4 m] 的 1 米范围内**，其余 32 个 global 点才均匀覆盖 [3, 80 m]。

与透视视图（DA3 深度正常）对比：

| 视图 | DA3 深度 | Surface 32 点范围 | Global 32 点范围 | 效果 |
|------|----------|-------------------|------------------|------|
| 透视 (d=20m) | 正常 | [16, 24 m] | [3, 80 m] | 表面附近密集，全局兜底 |
| 透视 (d=50m) | 正常 | [40, 60 m] | [3, 80 m] | 合理 |
| **鱼眼** | **0→3** | **[3, 4 m]** | [3, 80 m] | **约 50% 采样浪费在近处** |

---

## 六、影响总结

| 影响面 | 具体后果 |
|--------|----------|
| **沿射线的 3D 采样** | 鱼眼射线约 50% 采样点在 3–4 m，对远处物体几乎无分辨率；体渲染主要靠 32 个 global 点，精度远低于透视视图。 |
| **RGB loss 质量** | 体渲染 RGB 不准 → 与 GT 对比产生大 loss，梯度方向受错误采样影响，**产生噪声梯度**。 |
| **分割 loss 质量** | 分割渲染走同一套退化采样，分割监督质量同样下降。 |
| **作为 render 源** | 鱼眼做 render 视图时仅做颜色采样，**不受 DA3 深度影响**，行为正常。 |
| **对整体训练** | 约一半 loss 视图为鱼眼，其梯度质量差，相当于在正常梯度中混入大量噪声，**拖累收敛**，是 loss 平台波动的重要原因之一。 |

**结论**：鱼眼图像在训练中**完全参与**射线采样与 loss 计算，与透视视图地位相同；但因深度为零，自适应采样严重退化，来自鱼眼射线的梯度多为**噪声**而非有效信号。修复方式见《更稳定训练策略分析》中的 P1：对 DA3 深度无效（如鱼眼零深度）的射线**回退为与 S4C 一致的全局逆深度分层采样**（调用 `sample_coarse()`，`lindisp=True` 时为 disparity 空间线性+抖动，非深度空间均匀）。
