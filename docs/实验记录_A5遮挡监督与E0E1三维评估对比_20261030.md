## 6. 定量分析：A5 三维指标为何落后 E0/E1

### 6.1 差距量级

A5 三维 occupancy IoU 约为 E1 的 **0.44 倍（~2.3 倍差距）**，不是「一个数量级（10 倍）」。关键：**A5 的 Recall 只差 16 个点，Precision 差了 35 个点**——问题集中在 Precision。

### 6.2 IoU 损失分解（@12.8 m，用 `IoU = P·R / (P+R−P·R)` 反推）

| 反事实 | IoU | 相对 A5 变化 |
|--------|-----|--------------|
| A5 实测（P=26.82, R=62.78） | 23.14 | 基准 |
| 只把 Precision 拉到 E1（61.64），Recall 不变 | **45.1** | +22.0 |
| 只把 Recall 拉到 E1（78.94），Precision 不变 | 25.0 | +1.9 |

**结论：A5 三维 IoU 落后的 92% 来自 Precision 崩塌（过填充/假占用），仅 8% 来自 Recall 略降。**

### 6.3 Precision 崩塌的定量机制（理论下限 20%）

遮挡监督损失约束的是**累积权重**，不是逐体素稀疏：

```
surf_sum = Σ weights · surf_mask → 1，surf_mask 覆盖 z ∈ [d*−0.5, d*+0.5]
```

- `surface_band = 0.5 m` → 表面带 **1 m 宽** = `1 / 0.2 = 5 个 voxel`。
- 损失只要求 1 m 带内**累积**权重 = 1，**不惩罚**权重在 5 个 voxel 间摊薄。
- 累积 α→1 摊到 5 个 voxel，每个 voxel 的 σ ≈ 1~2，**远大于阈值 0.25** → 5 个 voxel 全判占用。
- GT 表面是薄层（≈1 个 voxel）→ 每条射线 `TP=1, FP=4` → **理论 Precision 下限 = 1/5 = 20%**。
- 实测 26.82%，紧贴 20% 下限，证实「表面带被均匀填满」确实发生。

E1 无此损失，继承了 S4C 收敛的自由空间场（自由空间 σ→0、表面薄层），因此 Precision 61.64%。

### 6.4 二维 depth 指标的实际数值（修正"差不多"表述）

> ⚠️ 本报告此前只有机制描述、没有数值，且"二维指标差不多"的表述不成立。这里补上对应 checkpoint 的数值，并修正结论。

**A5 的二维指标（Test@E4 ~46k，checkpoint 49500 前最后一次记录）**：

| 指标 | 类型 | A5 | E1（best，run3） | 基线（online DA3） |
|------|------|-----|------------------|--------------------|
| a1_lidar ↑ | 深度 | **0.711** | **0.8603** | 0.847 |
| abs_rel_lidar ↓ | 深度 | **0.201** | **0.1188** | 0.126 |
| seg_acc ↑ | 二维语义 | **0.602** | **0.6804** | 0.641 |

- E1 数值来自 run3 `out/s4c_dhs_rt_e1/..._20261029-225544` 的 tfevents 最佳 checkpoint：
  `best_1_model_60000_a1_lidar=0.8603`、`best_2_model_55000_abs_rel_lidar=0.1188`、`best_4_model_60000_seg_acc=0.6804`。
- A5 数值来自 `实验记录_A5遮挡监督_20261013.md` Test@E4。

**修正后的结论**：

1. **A5 的二维 depth 并不"差不多"，而是明显更差**：`a1_lidar` 0.711 vs E1 0.860（−0.149），
   `abs_rel_lidar` 0.201 vs E1 0.119（+69% 相对误差）。二维语义 `seg_acc` 0.602 vs 0.680 也低约 8 个点。
2. **原因主要是训练起点不同**：A5 从零训练且只跑到 Epoch 4（~46k iter），E1 从 S4C(176000) 权重热启动。
   A5 的 `a1_lidar` 只到基线终值的 83.9%（0.711/0.847），几何尚未收敛。
3. **§6.4 原"机制"只解释"遮挡损失不灾难性破坏 depth"**（累积权重中心钉在 d* 附近，对称摊薄不改变期望位置），
   它**不能支持"depth 与其它模型差不多"**。实测 A5 的 depth 是三者里最差的。
4. 因此正确的对比口径是：**三维 occupancy 上 A5 过补全（Prec 崩），二维 depth 上 A5 也未收敛到 E1 水平**——
   两者都指向"遮挡监督+从零训练"这条路整体弱于"RT+热启动"，而不是"二维好、三维差"的分叉。

### 6.5 结论

A5 的三维指标落后不是训练不足，而是**设计固有缺陷的定量表现**：三态遮挡监督用「累积权重→1」做表面监督，配合 `surface_band=0.5 m`（1 m 带 = 5 voxel），把表面信息摊薄到 5 个 voxel，系统性制造 ~4 倍假占用，Precision 逼近 20% 理论下限。

### 7.1 如何复现 A5 的二维指标（a1_lidar / abs_rel_lidar / seg_acc）

> 二维深度指标只由 trainer 的验证循环 Test@ 产出，**没有独立评估脚本**（`evaluate_model_sscbench.py` 只产 3D occupancy，`evaluator_lidar.py` 只产 o_acc/o_prec/o_rec）。
> 因此要在 49500 上拿到权威二维值，唯一可靠路径是**短时恢复训练触发一次 Test@**，复用当初产出 0.711/0.201 的同一机制。

**前置**：A5 的 `exp_kitti_360` 是旧配置（39 维 RT + occlusion loss），必须用 `occlusion-supervision` 分支代码才能正确 load。用 `git worktree` 隔离，**不要在 E1 训练运行中直接 `git checkout` 换分支**。

```bash
# 1) 隔离分支（不干扰正在跑的 E1 训练/评估）
git worktree add ../A5-test occlusion-supervision
cd ../A5-test && conda activate s4c

# 2) 短时恢复训练触发 Test@（49500 后下一个验证点是 50000）
python train.py -cn exp_kitti_360 \
  resume_from=out/kitti_360/kitti_360_backend-None-1_20261013-130859/training_checkpoint_49500.pt \
  reset_training_state=false \
  validate_every=1000 stop_iteration=600
```

- `reset_training_state=false` 恢复 optimizer/iteration 状态，从 ~49500 续跑；
- `stop_iteration=600` 让它跑到 50000 触发一次 Test@ 后自动终止，产物落在 `stop-on-600` 子目录，不污染原 run 的 checkpoint 编号；
- 终端会打印 `a1_lidar` / `abs_rel_lidar` / `seg_acc`（`save_best` 已配置这四项）。

**3D 复跑命令**（若需换口径重评，checkpoint 经 `out/kitti_360` 软链到 `/mnt/disk1`）：

## 9. 附：第一组消融（原实现 vs 单位修正）5000 步结果

> 独立于 E0/E1/A5 的单变量消融，量化「DA3 轴向 z 未转沿射线距离」这一单位错误的损失。

### 9.1 两组定义与「哪次跑错」

| 组 | config | `da3_z_to_distance` | 含义 |
|----|--------|---------------------|------|
| orig（原实现） | `exp_ablation_z2dist_orig.yaml` | **false** | **保留单位 bug：DA3 轴向 z 直接当沿射线距离（采样中心偏近）** |
| fixed（修正） | `exp_ablation_z2dist_fixed.yaml` | **true** | z / cosθ → 沿射线距离（采样中心正确） |

- **「跑错」的是 orig 组**：DA3 输出的是轴向 z-buffer（`z = d_ray·cosθ`），
  原实现直接把它当沿射线距离 `d_ray` 用 → 采样中心被低估 `cosθ` 倍、整体偏近，
  偏移量随像素偏离图像中心（cosθ 越小）单调增大。fixed 组才是修正。
- 两组除该开关外完全一致：S4C+DHS+RT(E1 103 维)、S4C 176000 warm-start（`reset_training_state=true`）、
  batch=8×acc2、`stop_iteration=5000`、`validate_every=1000`、n_surface/n_global=32/32。

### 9.4 结论

**4500 iter（≈ S4C 176000 的 2.5%）训练严重不足，两组差异在噪声范围内，无法据此判断单位错误的真实损失**：
IoU 无一致方向（|Δ| < 0.25），mIoU 三尺度一致略降（−0.15~−0.22，幅度极小）。
需将两组训练至收敛（≥ 20000–30000 iter）后重评，才能对「z→距离修正」下结论；
fixed 另有从 4500 继续到 17000 的续跑（`..._stop-on-30000/`），但尚无 3D 评测结果。
