# 漏检定位与 RT 密度诊断 (三模型逐体素对比, 固定检查点)

> 日期: 2026-10-30
> 分支: `s4c-dhs-rt-e2`
> 性质: **只读诊断, 不训练、不改权重**
> 脚本: `scripts/diagnose_voxel_miss_rt.py`
> 关联: `docs/采样点覆盖诊断与远距离Recall瓶颈_20261030.md` (采样侧), 本文 (占据/RT 侧)

---

## 0. 要回答的核心问题

E1 (S4C+DHS+RT) 相比 S4C 基线, Recall 随距离下降。单凭"远距离 95.35% 回退"
(采样诊断) 还不足以定位: 需要知道 **Ours 相对 S4C 丢掉的正确占据, 究竟在哪个环节
变为空**。本文用三个固定检查点在同一批验证帧上导出逐体素占据, 做漏检定位 + RT
密度诊断。

结论分两层:

- **Step 1 (代码核对, 已完成)**: DHS 的低置信度回退分支与 S4C 的真实采样**数值等价**,
  因此"远处全局采样稀疏"是两者**共同**的基线性质, 不能单独用它解释 Ours 的退化。
- **Step 2 (逐体素导出, 脚本已就绪待 GPU 运行)**: 定位漏检体素属于"RT 抑制 /
  RT 前密度低 / 分割头判空"三类中的哪一类, 决定下一步改 RT 还是改采样。

## 1. Step 1 结论: 回退分支 == S4C 采样 (代码核对)

### 1.1 S4C 真实采样 (基线)

`evaluate_model_sscbench.py` 在评估时强制:

```
renderer.renderer.n_coarse = 64
renderer.renderer.lindisp   = True
```

对应 `models/common/render/nerf.py` 的 `sample_coarse`: **64 点、逆深度分层、z_near=3、
z_far=80、lindisp=true**。S4C 没有 DHS 自适应采样, 所有像素都是这 64 点全局逆深度采样。

### 1.2 DHS 回退分支 (`sample_adaptive`)

`models/common/render/nerf.py` 的 `sample_adaptive` 中, 当像素满足:

```
invalid_depth (d_ray < z_near + 0.01)  或  norm_conf < conf_threshold(0.2)
```

时, 走 **回退**: 把该像素的所有采样点替换为 `sample_coarse(rays)` —— 即上面 S4C
用的同一个全局逆深度分层采样器。配置保证 `n_coarse = n_surface + n_global = 32+32 = 64`,
且 `lindisp=true`, near/far 相同。

### 1.3 结论

| 维度 | S4C 采样 | DHS 回退分支 |
|------|---------|-------------|
| 点数 | 64 | 64 (n_surface+n_global) |
| 分布 | 逆深度分层 | 逆深度分层 (同一 `sample_coarse`) |
| 逆深度开关 | lindisp=true | lindisp=true |
| 范围 | [3, 80] | [3, 80] |
| 是否有额外阶段 | 无 | 无 (回退即完全替换) |

**因此回退分支与 S4C 采样数值等价。** 采样诊断里"远距离回退间距 7.80m / 全局间距
12.87m"的稀疏, S4C 同样存在 —— 这是两者**共同**问题, 不是 Ours 独有的退化原因。
Ours 相对 S4C 的 Recall 差异, 必须从 **DHS 在非回退像素引入的表面采样 + RT 修正**
这两个 Ours 独有环节去找。

> ⚠️ 推论: 采样侧"回退关掉 95% 远距离表面采样" (见采样诊断文档 §4.1) 仍然是
> **Ours 无法超过 S4C 远距离 Recall** 的候选原因之一, 但它解释不了 **Ours 比 S4C
> 还差** 的部分 —— 那部分只能由 DHS/RT 的净负贡献解释, 即 Step 2 的目标。

## 2. Step 2: 三模型逐体素漏检定位 + RT 密度诊断

### 2.1 三个固定检查点

| 模型 | 检查点 | 说明 |
|------|--------|------|
| `s4c` | `/home/lmh/s4c/out/training_checkpoint_176000.pt` | S4C 基线 (无 DHS/RT) |
| `ours` | `out/s4c_dhs_rt_e1/s4c_dhs_rt_e1_backend-None-1_20261024-010315/training_checkpoint_53500.pt` | 论文 Ours (S4C+DHS+RT, `da3_z_to_distance=false`) |
| `e1` | `out/s4c_dhs_rt_e1/s4c_dhs_rt_e1_backend-None-1_20261029-225544/best_2_model_55000_abs_rel_lidar=-0.1188.pt` | 修复后 E1 (`da3_z_to_distance=true`, step 55000; `training_checkpoint_55000.pt` 已被后续训练覆盖删除, `best_2` 为该步非 EMA 权重, 与 eval IoU 52.42 对应) |

> **关键加载陷阱**: `configs/exp_kitti_360.yaml` 默认 `ray_attention.enabled=true`。
> S4C 检查点**没有** `ray_attention.*` 权重, 若按 DHS 配置构造 BTSNet 会得到一个
> **随机初始化**的 `RaySigmaCorrector`, 给 S4C 施加随机密度修正 → 不再是真正的
> S4C 基线。脚本对 `s4c` 强制 `ray_attention.enabled=False` (见 `MODELS["s4c"]["rt_enabled"]=False`)。

### 2.2 占据判定 (与评估完全一致)

```
occ = grow(sigma) >= SIGMA_CUTOFF(0.25)  且  分割头 argmax 映射后 label > 0
```

- `grow`: 3×3×3 max-pool (与 `USE_GROW` 一致)。
- `sigma`: 模型最终密度 (RT 修正后)。
- `seg_label`: 分割头 19 类 argmax → `cityscapes_to_label` 映射到 SSCBench label;
  sky/rider → 0 (视为空)。等价于评估里 `segs[sigmas < cutoff] = 0` 后的 `segs > 0`
  (因 sigma=softplus(·)>0, `argmax(σ·softmax)` ≡ `argmax(softmax)`, 与 eval 逐点一致)。

### 2.3 四组体素集合 (全部限制在有效掩码 `eff = FOV & (target!=255)` 内)

| 集合 | 定义 | 要回答的问题 |
|------|------|-------------|
| set1 | `gt_occ & occ_s4c & ~occ_ours` | 原设计 (DHS+RT) 丢掉了什么 |
| set2 | `gt_occ & occ_ours & ~occ_s4c` | 原设计改善了什么 |
| set3 | `gt_occ & ~occ_ours & occ_e1` | 当前修复 (`da3_z_to_distance`) 恢复了什么 |
| set4 | `gt_empty & occ_e1` | 修复付出了多少误报 |

### 2.4 set1 的 RT 密度诊断 (三分类)

对 set1 漏检体素, 导出 Ours 模型的 **RT 前密度 base / RT 残差 (logit) / RT 后密度
post / 最终占据判定**, 归入三类:

| 类别 | 判据 (raw, 未膨胀) | 含义 | 下一步 |
|------|--------------------|------|--------|
| RT 抑制 | base>0.25 且 post≤0.25 | RT 把本应占据的体素压到阈值下 | **优先 E2 的 RT 消融** |
| RT 前密度低 | base≤0.25 | RT 之前密度就低于阈值 | 原因待分析 (采样/梯度/损失, 不能直接归采样) |
| 分割头判空 | base>0.25 且 post>0.25 且 seg_label=0 | 密度够但分割头预测 sky/rider | 查分割头 (与 RT/采样无关) |

> 三类互斥且**应恰好穷尽 set1** (若 base>0.25 且 post>0.25 且 seg_label>0, 则
> grow(post)>0.25 且 occ=1, 不可能落在 set1)。输出里三类百分比之和应 ≈100%。

### 2.5 RT 诊断量在模型里的钩子 (`models_bts.py`)

`BTSNet.__init__` 新增 `self.return_rt_diagnostics` (conf key, 默认 False) 与
`self._rt_diagnostics`。`forward()` 中仅当 `return_rt_diagnostics=True` 时捕获:

- `rt_base_sigma = softplus(raw_sigma).detach()` —— RT 修正**前**密度
- `residual = sigma_correction.detach()` —— RT 输出的 σ 修正 (logit 空间)
- `post_sigma = sigma.detach()` —— RT 修正**后**最终密度

无 RT 的模型 (S4C) 或不传 `ray_K` 时, 残差为 0、前后一致。该钩子**可逆**, 默认关闭,
不影响训练/评估。

### 2.6 脚本加载自检 (CPU, 2026-10-30) 与已知 eval 基线

脚本在交付前做了 CPU 加载自检 (三个检查点均在 CPU 上成功重建 BTSNet + 加载权重):

| 模型 | `ray_attention_enabled` | `mlp_coarse.lin_in.weight` 输入维 | 结论 |
|------|--------------------------|-----------------------------------|------|
| `s4c` | False (脚本强制关闭) | (64, 103) = 64 feat + 39 xyz_code, **无 RBF** | 重建为纯 S4C 基线, 无随机 RT 干扰 |
| `ours` | True | (64, 103), 无 RBF | RT (RaySigmaCorrector) 权重已加载 (非随机) |
| `e1` | True | (64, 103), 无 RBF | RT 权重已加载 |

自检中发现并修复的四处问题 (均已通过 `py_compile` + CPU 加载/前向验证):

1. **`e1` 检查点路径错误**: 原写 `training_checkpoint_56500.pt` **不存在** (该步
   `training_checkpoint_55000.pt` 被后续训练覆盖删除)。改为同目录的
   `best_2_model_55000_abs_rel_lidar=-0.1188.pt` (step 55000 的非 EMA 权重, 与
   `evaluation_training_checkpoint_55000` 的 IoU 52.42 对应)。
2. **补上 RBF 自动检测**: `load_model` 复刻 eval 的逻辑, 按 `lin_in.weight` 输入维
   设 `use_rbf_encoding` (103→False)。三个检查点均 103, 无影响, 但保证与 eval 一致。
3. **Hydra `config_path` 必须相对**: `initialize(config_path=...)` 传绝对路径会抛
   `HydraException`, 改为相对调用文件的 `"../configs"` (脚本在 `scripts/` 下)。
4. **`predict_occupancy` 的网格张量类型**: 脚本主流程把 `cam_pts` 转成 numpy 网格
   `pts_grid` 传入; 但 RT 分支 `pts_seg.permute(1,2,0,3)` / 非 RT 分支
   `pts_flat[...].unsqueeze(0)` 都是 torch 语义, 对 numpy 会 `AttributeError`。
   eval 里 `predict_grid` 收到的 `points` 是 device 上的 torch 张量 (经
   `downsample_and_predict` 传入)。已在 `predict_occupancy` 内把 numpy 网格统一转
   `torch.from_numpy(...).to(device).float()`, 与 eval 行为对齐。

另有一处对齐修正: 占据阈值判定由 `> SIGMA_CUTOFF` 改为 `>= SIGMA_CUTOFF`, 与
eval 的 `segs[sigmas < SIGMA_CUTOFF] = 0` (即 `sigmas >= cutoff` 才占据) 严格一致
(实际对 softplus 连续输出是零测度差异, 但保持口径统一)。

**整帧前向冒烟测试 (CPU, 假数据) 结果**:

| 模型 | 路径 | 前向 | RT 残差 | base vs post |
|------|------|------|---------|--------------|
| `e1` (RT on) | `best_2_model_55000_abs_rel_lidar=-0.1188.pt` | sigma/seg 形状正确 (X,Y,Z) | \|residual\| mean 0.139, max 1.25 | 不等 (RT 生效) |
| `s4c` (RT off) | `/home/lmh/s4c/out/training_checkpoint_176000.pt` | 形状正确 | 0.0 | 全等 (无 RT) |

即 `return_rt=True` 的诊断钩子能正确捕获 RT 前密度 (base)、残差、RT 后密度 (post),
且 S4C 无 RT 时残差恒 0 —— 与 `models_bts.py` 的 `_rt_diagnostics` 语义一致。

**已知 eval 基线 (仅作参考, 协议不完全一致)**: `evaluation_training_checkpoint_53500`
给 `ours` IoU **52.94** (Prec 61.64 / Rec 78.94, size 12.8); `evaluation_training_
checkpoint_55000` 给 `e1` IoU **52.42** (Prec 60.82 / Rec 79.16)。注意 S4C 仓库自己的
`evaluation_training_checkpoint_176000` 报 **26.95** 是 `USE_GROW=False` 口径; 本诊断
对三模型统一用 `USE_GROW=True` (与 DHS 仓库 eval 一致), 因此 S4C 基线在本脚本里会显著
高于 26.95, **不能**用 26.95 与 52.94 直接比。以本脚本 [A] 段的三模型同口径指标为准。

## 4. 如何下结论 (拿到结果后按此判读)

> 2026-10-30 复核修订: 早期判读有两点过度推断, 已纠正 (见 §6.4)。
> (1) [D] 的 "RT 前密度低" 只能说明"base 在 RT 前就低于阈值", **不能**直接归因于采样监督;
> base 是与 RT 联合训练出来的, 密度低还可能来自 RT 对梯度/分工的影响。
> (2) set1 只含"最终空"的交集, 不能代表 RT 的全局作用; RT 是否净有害必须看 [F] 的 IoU 与 [E] 的 GT-empty 翻转。

1. **看 [B] 的 set1 占 GT-occ 比例**: 仅描述"最终丢失"的规模, 不能单独下采样/RT 结论。
2. **看 [D] 的三分类占比** (raw 口径, 仅 set1 内):
   - `RT 抑制` 占比高 → RT 在该集合内压掉了占据, 但仍需 [F] 判断全局是否有益。
   - `RT 前密度低` 占比高 → 只是"base 在 RT 前就低于阈值, **原因待分析**" (不能直接归采样)。
   - `分割头判空` 占比高 → 与 RT/采样无关, 是分割头的召回问题。
3. **看 [C] 每桶漏检率** (set1数 / 该桶 GT-occ 数): 绝对数集中在中/远只能说明 GT 本身多;
   漏检率才能说明"单位占据体素"的丢失概率是否随距离上升。
4. **看 [E] 全局 RT 翻转** (grow+seg 口径): 同时看 GT-occ (flip_off/flip_on) 与 GT-empty
   (消除误报/新增误报)。RT 可能用部分 Recall 换取 Precision —— 只看一侧无法判断净益。
5. **看 [F] base vs post 混淆矩阵**: 直接比较两者的 Recall/Precision/IoU。
   若 post 的 IoU ≥ base → RT 总体有益; 若 post 的 IoU < base → RT 净有害, 优先 E2 消融。
6. **看 [G] Ours→E1 双向转移**: 区分"恢复/丢失"(GT-occ) 与"新增/消除误报"(GT-empty),
   不要只拿 set3(恢复) 解释 E1 的改善 —— 同时有大量丢失/误报替换。
7. 采样与 RT 都很明显 → **分开消融, 先不要合并修改**。

### 6.2 关键拆解: RT 的召回侧净抑制 (密度口径, 暂缺精度侧)

§4 判读的陷阱: 若只看 [D], "MLP 本来就空 97.9%" 会让人误判为"采样监督问题"。
但 [D] 只统计 set1 (最终空) 内部; 它没有计入 base 在别处对 S4C 的**补偿性增益**。
用 [A]+[E] 做边际拆解才能得到真实归因:

```
base 召回 (ours, 关 RT 的假想) = final + flip_off - flip_on
  = 62.86% + (136,823 - 34,964)/3,539,770
  = 62.86% + 2.88% = 65.74%
```

| 归因 | 召回损失 | 占缺口 (3.65%) |
|---|---|---|
| RT 净抑制 (flip_off≫flip_on, 残差负偏) | **2.88%** | **~79%** |
| DHS base MLP 相对 S4C 净不足 | 0.77% | ~21% |
| 合计 (s4c 66.51% − ours 62.86%) | 3.65% | 100% |

含义: **DHS 自适应采样的 base MLP 本身只比 S4C 差 0.77% (大致持平)**; 真正把
Ours 从 ~65.7% 拉到 62.9% 的是 Ray Transformer 的系统性负偏抑制——它把 base 正确
预测占据的 136,823 个体素压空, 却只救回 34,964 个 (净 −101,859 ≈ −2.88%)。

set1 内 "MLP 空 97.9%" 与上面的结论不矛盾: base 虽然在这 27 万个 S4C-正确体素上
没激活, 但在别处对 S4C 有 ~27.9 万体素的补偿性增益, 净差只有 2.7 万 (0.77%)。
而 RT 只在这 27 万里压掉 5,224 个, 却在全局压掉 13.7 万个 base 正确占据——RT 的
伤害主体不在 set1, 而在"base 本已改善于 S4C、被 RT 抹掉"的那部分。

> 复核注意 (2026-10-30): 上表是**召回侧、密度口径**的边际拆解, 不是最终结论。
> (1) base 是 `softplus(raw_sigma)` 的诊断量, **与 RT 联合训练**, 不是独立训练的无 RT 模型,
> 故 "base 净差 0.77%" 不能直接归为"采样没问题"。
> (2) 这里只算了 RT 对召回 (GT-occ) 的影响; RT 在 GT-empty 上消除了多少误报 (可能换回 Precision)
> 尚缺数据。只有 [F] 的 base/post IoU 对比才能判断 RT 总体是否有益。见 §6.4。

### 6.3 结论 (暂定) 与下一轮实验

当前**只能确定**:

- Ours 相对 S4C 的召回缺口 = set1 − set2 = 3.65% (净丢 ~12.9 万 GT-occ 体素)。
- RT 的召回侧净抑制为 2.88% (flip_off 13.68万 ≫ flip_on 3.5万), 即 base 密度若不被
  RT 压低, 召回应约 65.7% ≈ S4C。
- set1 内 97.9% 是 "RT 前密度已低于阈值", 但这是**原因待分析** (base 与 RT 联合训练),
  不能直接判为采样监督不足。

**尚不能下结论**:

- RT 是否总体有害。RT 可能用 2.88% Recall 换回部分 Precision; 需 [E] 的 GT-empty 翻转
  与 [F] 的 base/post IoU 对比才能判定 (post IoU ≥ base ⇒ RT 总体有益)。
- 采样是否需要优先调整。base 净差仅 0.77%, 但 set1 的 97.9% "RT 前空" 的真实成因
  (采样分布 / RT 梯度耦合 / 损失) 尚未区分。

**下一步 (重跑脚本即可补齐, 无需训练)**:

1. 重跑 §3 命令, 产出 [E] GT-empty 翻转 + [F] base/post 混淆矩阵 + [G] Ours→E1 双向转移。
2. 依 [F]: post IoU < base ⇒ P0 做 E2 RT 消融; post IoU ≥ base ⇒ RT 非主因, 回到采样/监督。
3. 依 [G] 量化 E1 的 "恢复 vs 丢失" 与 "新增 vs 消除误报", 修正 set3/set4 的过度解读。
